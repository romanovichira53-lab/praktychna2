Мета контейнеризації полягає в тому, щоб упакувати наш 
додаток разом із усіма його налаштуваннями та бібліотеками 
в один ізольований контейнер, який зможе запускатися на 
будь-якому комп'ютері абсолютно однаково. Головна перевага 
такого підходу полягає в тому, що він забезпечує повну 
стабільність роботи та повну незалежність від системного 
середовища, роблячи розгортання швидким і надійним.
Під час виконання практичної роботи я пройшла три основні 
етапи. Спочатку виконала збірку за допомогою Dockerfile, 
сформувавши готовий образ додатку з усіма необхідними 
залежностями. На другому етапі запустила контейнер у фоновому
режимі, вказавши порт 8080, змінну середовища та іменований 
том для логів. На третьому етапі провела перевірку 
працездатності сервісу за допомогою команди curl та 
переконалася, що все працює коректно.
Для збірки Docker-образу використала команду: docker 
build -t student-app . Для запуску контейнера у фоновому 
режимі з налаштуванням порту 8080, змінної середовища та 
іменованого тому для логів виконала команду: docker run -d 
-p 8080:8080 -e APP_NAME=student-demo -v app_logs:/app/logs 
ira/app:1.0
А для перевірки працездатності скористалася командою:
curl http://localhost:8080
Під час перевірки результатів контейнер успішно стартував у 
фоновому режимі, порт 8080 коректно зв'язався з хост-системою, 
а передана змінна середовища та створений том для логів 
спрацювали без жодних помилок. Звернення до сервісу 
підтвердило його повну працездатність і стабільність.
Під час виконання лабораторної роботи я ознайомилася з 
процесом контейнерування програмного забезпечення за 
допомогою Docker, навчилася збирати образи та запускати їх із
налаштуванням портів, змінних середовища й іменованих томів. 
У процесі роботи спочатку виникли невеликі труднощі з 
правильним прокиданням порту 8080 та перевіркою роботи 
через командний рядок, проте після налаштування параметрів 
контейнера все запрацювало.
